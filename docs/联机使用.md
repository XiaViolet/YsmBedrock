# 联机使用

基岩版 Windows 客户端使用相同的 YsmBedrock 版本。服主为一个基岩服务器启动一个 YSM 中继。模型始终由服主从有权分发的 ZIP 或受支持的 `.ysm` 中选择。

## 服主配置

把要发布的模型包和 `房间.json` 放在同一目录。为每位玩家运行一次 `py -3 ysm_relay.py --new-token` 生成独立口令。把下例中的玩家 ID 替换为该玩家的 Xbox 用户 ID。省略玩家条目的 `models` 时，该玩家可选择目录中的全部模型。填写空数组可浏览其他玩家的已发布外观。

```json
{
  "models": ["模型包.zip"],
  "players": {
    "1234567890123456": {
      "token": "填入刚生成的该玩家口令",
      "models": ["模型包.zip"]
    }
  }
}
```

本机验证使用以下命令。运行目录包含发行包内的 `ysm-inspect.exe` 和 `ysm_relay.py`。

```powershell
py -3 ysm_relay.py --config 房间.json
```

其他电脑连接时，使用服务器的受信任 HTTPS 证书启动中继，并指定可访问的地址，例如 `--bind 0.0.0.0 --cert 中继证书.pem --key 中继私钥.pem`。中继默认端口为 19140。

## 玩家配置

在基岩版实例的 `mods/YsmBedrock` 目录创建 `relay.json`。`bedrock_host` 和 `bedrock_port` 填玩家加入的游戏服务器地址与端口，`relay` 填服主提供的中继地址。每位玩家只保存自己的口令。

```json
{
  "enabled": true,
  "bedrock_host": "mc.example.net",
  "bedrock_port": 19132,
  "relay": "https://ysm.example.net:19140",
  "token": "填入自己的口令"
}
```

进入服务器后，模型库里标有「服务器」的选项可以按需下载和启用。其他玩家启用的模型也会按需下载到 `relay-cache`。改变贴图、换装或播放转盘动作后，已连接的相应客户端会收到状态。关闭模型或离开对应服务器时恢复原来的玩家皮肤。连接结果写入 `relay-status.json`。

中继使用基岩版移植版的协议。加入同一个服务器的两个客户端需分别完成 Windows 实机外观验收。

0.29.5 随玩家状态同步左右肩鹦鹉的实体 ID。中途加入的观察者可以取得当前肩位，接收端用实际骑乘关系核实这只鸟；本地宿主优先采用世界存档。两个原生网络观察端已测，第二名玩家屏幕上的实际效果仍待验证。

0.29.5 的中继按在线接收方、连接会话和模型确认脚本事件。每包最多 64 条；已订阅接收方暂时落后时，中继最多保留 256 条，再由发送方保留尚未确认的部分并重试。发送端待发队列最多 4,096 条，溢出会产生诊断。接收方离线超过 8 秒后不再阻塞发送；刚加入的玩家及旧协议接收方能取得最近一页。角色持续状态仍可在重连时重新取得。
