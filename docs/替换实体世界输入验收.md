# 0.29.3 替换实体的天气、露天状态与类型标签

Java 端使用 Minecraft 1.21.1、Fabric Loader 0.18.4 和 YSM 2.6.5 正式版。Windows 端使用 Minecraft 1.26.60.05、LeviLamina 26.60.8 和 YsmBedrock 0.29.3。测试发生在主世界。两端加载同一个独立测试模型 WorldInputs.zip，SHA-256 为 `45c22018981392f236954b505283133840dc2f0f99cbb9b630f3939f8ca6693b`。Java 正式版 JAR 的 SHA-256 为 `a66b7265a2761d639c48f61a64179206adf5d81c38f360763fc8275a0fec9fa5`。

## 首个差异与修复

| 行为 | 首个差异 | 共用修复 |
| --- | --- | --- |
| 替换实体读取 `ysm.weather` | 箭和船的宿主输入遗漏当前世界的雨和雷，脚本可以正常求值却读到默认晴天 | 玩家、箭和船从被采样实体所在世界读取同一份天气快照，在绑定 Molang 前写入输入。遮顶后天气值继续反映世界天气。 |
| 替换实体读取 `ysm.is_open_air` | 首先漏采实体脚下所在列。补采后的首个候选构建又把玻璃顶下的船判为露天，照明高度忽略了透明玻璃 | 从实体自身的维度和脚下坐标取区块、天空可见性及阻挡高度。采用包含固体与液体的原生高度查询。实机确认石顶、玻璃顶与移除遮挡后的行为。 |
| `#类型标签` 的目标选择 | 绘制和诊断路径都把 `Actor::getTags()` 传给模型匹配器，先声明的错误目标能抢占替换 | 两处按实体注册 ID、变体和已知类型标签选取。保留按声明顺序选择首个有效目标。 |

上游定位点为固定源码 `15c2c25` 的 `EntityBuiltins.isOpenAir`、`ModelIdUtil`、`CustomVehicleEntity` 和 `CustomProjectileEntity`。本轮基岩实现位于 `NativeBlockQueries.cpp`、`AnimationRuntime.cpp` 和 `NativeReplacedResources.cpp`。控制器诊断记录运行时实际应用的片段名，可用实体 ID 对到绘制记录。

## 双端实机

同一测试包分别为船和实射的有主箭提供六个独立命名的动作。Java 记录正式版查询函数返回值和动画播放器正在采样的片段。基岩记录同一实体的 Molang 读值、控制器状态、已应用片段名、Base 骨骼位移与原生骨骼应用数。对照取世界条件稳定的采样，客户端的 tick 各自计数。切换过程中跨越多个渲染帧的 Java 样本保存在原始记录中。

| 世界条件 | `ysm.weather` | `ysm.is_open_air` | 船动作后缀 | 箭动作后缀 |
| --- | ---: | ---: | --- | --- |
| 晴天露天 | 0 | 1 | clear_open | clear_open |
| 晴天遮顶 | 0 | 0 | clear_roof | clear_roof |
| 下雨露天 | 1 | 1 | rain_open | rain_open |
| 下雨遮顶 | 1 | 0 | rain_roof | rain_roof |
| 雷暴露天 | 2 | 1 | thunder_open | thunder_open |
| 雷暴遮顶 | 2 | 0 | thunder_roof | thunder_roof |

12/12 个组合的两端读值与动作名一致。船动作前缀为 `wx_vehicle_`，箭为 `wx_projectile_`。基岩实机还读到对应的 Base 位移 `[天气值, 露天值, 1]`，船与箭分别有 6 和 8 根原生骨骼应用记录。雷暴中只在箭上方放玻璃，船同时保持露天，两者各自播放对应动作。

标签试验先在船上添加实例标签 `minecraft:arrows`，在箭上添加 `minecraft:undead`。清单故意将这两个会误命中的目标排在各自第一位。Java 的实体数据读回了两个标签，基岩的双实体条件命令返回 `WX_both_instance_tags_present`。两端实际片段均为 `wx_` 开头。基岩绘制记录中的船 `-1039382085631` 选择 `vehicle/0001`，箭 `-1043677052924` 选择 `projectile/0001`。后者依靠正式类型标签 `#minecraft:arrows` 匹配。

## 原包回归与范围

按相同的晴雨、遮顶和弓弩输入，比较 0.29.2 与 0.29.3 的原包目标、骨骼姿态、控制器状态、内置动作及粒子和声音事件。临战爱丽丝、香奈美生贺 v1.0.3、官方原包战术狐的箭各回放 24 帧，姿态最多分别包含 257、4、12 根骨骼。战术狐静态船另回放 24 帧。96 帧输出一致，表达式错误均为零。原包 SHA-256 与输出摘要见 original-regression.json。

这三份原包所声明的载具、投射物动作与控制器文件共 11 份，其中未发现对这两个天气查询的直接引用。新增天气动作的可见收益适用于作者实际写了这些条件的包。已知原包的检查覆盖已有动作与目标继续工作。

本轮验证主世界稳定天气、露天与遮顶。天气渐变时切换动作的具体帧、流体与特殊方块的高度边界、其他维度和 Java 数据包自定义的类型标签仍待双端验证。下一批优先核对同刻切换手持物与发射时 `ysm.shoot_item_id` 的事件顺序。

## 复验资料

验收归档 `YSM-0.29.3-世界输入验收.zip` 内的 comparison.json 为逐项索引，含两端实体 ID、逻辑 tick、片段名和基岩骨骼位移。java-live.tsv、java-extra.tsv、bedrock-live.json 保存原始采样，bedrock-tagged-routes.json 保存绘制与归属记录，java-confirmed-tags.txt 为 Java 标签回读。运行 `python compare.py` 可从这些文件重算 12 项结果。WorldInputs.zip 可直接放入两端的测试模型目录。

884 项自动检查通过。新增的 `tests/test_replaced_world_inputs.py` 用同一份 WorldInputs.zip 回放全部 12 个组合，断言目标 ID、控制器状态、实际应用的动作及骨骼位移。
