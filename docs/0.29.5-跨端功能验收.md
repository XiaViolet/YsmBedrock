# 0.29.5 跨端功能验收

本轮使用 Minecraft Java 1.21.1、Fabric 0.18.4、Yes Steve Model 2.6.5 正式版，以及 Minecraft for Windows 1.26.60.05、LeviLamina 26.60.8。Java 模组 JAR 的 SHA-256 为 `a66b7265a2761d639c48f61a64179206adf5d81c38f360763fc8275a0fec9fa5`。工程固定源码为 `15c2c25`。下列文件名相对于同版验收 ZIP；作者原包只记标识及校验值。测试夹具与原包各自独立。[总对照表](Java功能对照.md) · [Java 正式版](https://modrinth.com/mod/yes-steve-model/version/eGOUtHWJ)

## 实体目标振动和脚本顺序

在 Java 客户端的模型脚本指定振动的 `destination.type = minecraft:entity`。目标实体存在、移动或不存在，以及 UUID 使用 SNBT 整数数组或列表，结果均为客户端粒子参数解码失败。已经发出的前一颗粒子保留，同次表达式后续指令停止。下一次独立求值仍然可以成功。合法的方块目标是正对照。把 UUID 解析成世界坐标并追踪实体会添加 2.6.5 正式版在此入口没有的可见行为。

基岩在相同的粒子参数解析边界停止当前求值，保留已经提交的效果。共用 Molang 对负数平方根按正式版返回零，后面的脚本继续执行。基岩实机夹具可见方块振动，错误参数后面的 `end_rod` 分派计数为零。Java 实机记录见 `particles/java-summary.json`。八份可读原包没有命中这组粒子的字面名称；爱丽丝、昔涟和香奈美使用了平方根，是否进入负数分支取决于游戏条件。

## 肩上鹦鹉

实测正式包只匹配每侧的精确骨名 `LeftShoulderLocator` 和 `RightShoulderLocator`。只有带编号的骨时该侧不绘制，有同名规则的主骨与编号骨时只绘制一次。世界内的鸟获得作者从根到定位点的骨骼变换。两份未修改原包分别为战术狐和临战爱丽丝。

基岩根据玩家和肩上鹦鹉的实体 ID 跟踪肩位，使用当帧求值后的作者骨骼矩阵变换原生鹦鹉。原生引擎在一只鸟离开后会压缩座号，这曾使幸存的右肩鸟跳到左肩。Java 八组实际矩阵同基岩共用代码回放比较，16 个元素的最大绝对差为 0.000000285。矩阵、原包左右肩及空肩图见 `shoulder/`；编号骨对照见 `shoulder-edge/`。

保留单只右肩鸟，再完全退出并重启两端。Java 同一只右肩 Variant 2 在重进后仍选头骨下的 `RightShoulderLocator`。基岩同一只鸟 -1095216660478 的原生座号依次为 1、0、0；存档中记录主人与右侧标记。固定相机下，冷重进绘制位置距原右肩 0.01116 格，距原左肩 0.25479 格。录像为 `shoulder/肩位与冷重进.mp4`，实体 NBT 和逐帧记录在同目录。

战术狐的生存背包中，旧实现把右鸟提交到了预览框外。改用预览人偶的足底、姿态和投影后，鸟出现在头顶。Java 空肩、右鸟、再次空肩三张图的框内绿色像素为 0、244、0。基岩固定肩鸟，在两种世界镜头下分别看到 465 与 603 个绿色像素，卸下后为 0。两端各用自己的原生鸟。另测临战爱丽丝的 Java 原包，右鸟的绘制已提交，但头顶超出背包预览裁切范围。图像见 `shoulder-menu/`、`shoulder-menu-alice/` 与 `shoulder/肩位验收.md`。

在最终的投影判定下，同一只绿鸟在第三人称世界使用透视投影，在生存背包使用正交投影。战术狐背包里有鸟与空肩的固定区域分别有 519 和 0 个绿色像素。见 `shoulder/projection-comparison.json` 和 `shoulder/bedrock-final-projection-*.jpg`。

HUD 的 YSM 角色小窗另有独立绘制入口。用战术狐在 Java 正式客户端开启角色小窗、空肩→挂右鸟→卸下。固定头部区域的绿色像素为 0、885、0。基岩小窗使用当前玩家动作和作者定位骨，读取游戏资源包内的鹦鹉几何、坐姿及实际变种贴图，和人物在同一深度缓冲绘制。挂鸟和卸下后头顶区域分别有 895 和 0 个绿色像素。见 `shoulder-hud/hud-comparison.json`、`shoulder/hud-comparison.json` 和 `shoulder/HUD挂肩与空肩.png`。

在第一人称直接冷启动，再次检查肩鸟是否会改变小窗人物的取景。战术狐入场挂鸟、卸鸟、同姿态重新挂鸟时，固定区域分别数到 596、0、592 个绿色像素。同姿态两只红袖及双靴的水平边界相同，垂直边界相差最多 1 像素。人物沿自身骨骼确定取景范围，肩部附件随人物投影。两端实拍并排见 `shoulder/HUD双端对照.png`，逐区域测量见 `shoulder/hud-firstperson-comparison.json`。

## 重进世界后的替换实体

Java 冷启动前后跟踪同一支普通箭和同一艘船。玩家换模后，存档中的实体仍绑定它生成时的原模型。重新创建客户端箭实例时，`ysm.shoot_item_id` 重新取持有者当时的主手。临战爱丽丝用弓发射并换拿木棍，实测得到 `bow → stick`；战术狐独立复验得到同样的结果。船若有归属、但所属原包没有声明对应替换目标，游戏保留原版船，诊断应停在目标匹配。

基岩将模型来源、内容标识和相关归属状态随宿主世界中的实体保存。两个显示名相同的存档包含相同数值的三叉戟 ID，仅原世界的实体 NBT 带爱丽丝归属。详见 `ownership/world-isolation.json` 和 `ownership/java-reentry.json`。

基岩完整退出进程，把当前模型换为爱丽丝，重新进入战术狐的世界。箭 -1082331758590 的发射物品由弓变木棍，同一艘船 -1082331758591 仍绘制 `vehicle/0002` 黄快艇，同一把三叉戟 -1030792151031 仍绘制 `projectile/0001`；旁边未被骑乘的普通船保持原版。爱丽丝世界的三叉戟冷重进后仍选中 `projectile/0003`，该作者未为受测船声明目标。两份原包在两个客户端逐文件一致。见 `ownership/归属验收.md`、`ownership/fox-comparison.json` 和重进前后实拍。此项验收针对本地宿主世界。远端专服仍需要服主端将实体的持久归属发给追踪它的观察者。

战术狐还用同一支箭观察了作者的漫游变量（roaming）。在 Java 正式版里，发射时变量为 1，箭牌隐藏；改为 0 后，服务器保存了 0，已显示的那支箭仍隐藏。冷重进时箭牌按 0 显示，此后玩家改回 1，旧箭仍显示。箭和船的 UUID 以及四次服务端值见 `ownership/roaming-compare.json`，四帧实图见 `ownership/fox-roaming-visible.png`。正式版内置 default 原包用独立键得到相同的存储行为。基岩已分开处理存储数据与客户端渲染快照，已加载、重连及换模的状态有原生回归。

另测 Java 隐藏玩家模型的指令。战术狐的同一支红白箭在隐藏本人前、隐藏后、冷重进、重新显示本人四帧中均可见。基岩已在共用渲染和诊断入口允许本地已绑定实体继续显示，远端仍采用服主授权与观察者的可见性设置。对照图见 `ownership/java-model-disable.png`。此外，战术狐有非空 roaming 变量的旧箭曾在归属与动作都正确时退回原版，故障在原生模型创建。修正后每个替换实体使用已就绪的玩家渲染模板。按同一实体 ID 的重进复验见 `ownership/归属验收.md`。

原生模板可从引擎已注册的玩家渲染器取得。关闭 HUD 角色小窗，让自由镜头避开玩家，全新进程重进战术狐世界。第 71 刻，同一支旧箭 -1082331758587 已有 726 次网格绘制。第 271 刻已绘制 9,300 次，求值与绘制覆盖 17 块骨骼，`Board` 按存档 a=b=1 缩放为零。较早的独立启动中，关闭本人模型之后，旧箭和已下船的船也继续绘制。见 `ownership/flags-reentry-comparison.json`、`ownership/flags-dispatcher-first.json` 和 `ownership/bedrock-fox-roaming-visible.png`。
