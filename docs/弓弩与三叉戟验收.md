# 弓弩与三叉戟实机验收

基线是 YsmBedrock 0.29.0，修复版是 0.29.1。Java 实测为 Minecraft 1.21.1 Fabric、YSM 2.6.5，基岩版为 Minecraft 1.26.60.05、LeviLamina 26.60.8。作者资源在两个测试实例里使用相同文件内容，测试后 163 个原始文件的 SHA-256 全部一致。

## 原包声明

| 原包 | 声明与资源 |
| --- | --- |
| 临战爱丽丝·箭 | `files.projectiles.arrow` 使用 `models/arrow.json`、`textures/arrow.png`、`animations/projectiles/arrow.animation.json`。动作有 `air`、`air2`、`animation.unknown.new`、`fire`、`ground`、`parallel1` 至 `parallel7`、`water`。`parallel1` 根据 `ysm.shoot_item_id` 控制 `Aris-guanpao-z`（弓）和 `Aris-gun-z`（弩）。 |
| 临战爱丽丝·三叉戟 | `files.projectiles.trident` 使用 `models/trident.json`、`textures/trident.png`、`animations/projectiles/trident.animation.json`。动作有 `air`、`fire`、`ground`、`parallel0` 至 `parallel6`、`pre_parallel7`、`water`。 |
| 香奈美生贺 v1.0.3·箭 | `parallel0` 同样读取 `ysm.shoot_item_id`，控制 `ysmGlowbow` 和 `ysmGlowcrossbow`。本轮实射使用临战爱丽丝。 |
| 战术酒狐·三叉戟 | Java YSM 内置原包 `wine_fox/16_tactics`，目标 `minecraft:trident`。使用 `models/trident.json` 和 `textures/trident.png`，作者只提供静态投射物外观。双端均用该原包复验。 |

## 实投记录

表中 Java 和基岩版 ID 分别来自各自的世界。基岩版测试玩家 ID 为 `-4294967295`。两支箭使用同一原版普通箭，发射和换到木棍发生在同一游戏刻。

| 项目 | Java ID | 基岩版 ID、匹配与绘制 | 验收 |
| --- | --- | --- | --- |
| 弓 | `242` | `-1030792151039` → `projectile/0000`，保留 `minecraft:bow`，`air` → `ground`，`Aris-guanpao-z` 可见，`Aris-gun-z` 缩为 0。游戏画面可见紫色投射物与命中效果。 | 基岩版通过 |
| 弩 | `244` | `-1030792151038` → `projectile/0000`，保留 `minecraft:crossbow`，`air` → `ground`，`Aris-gun-z` 可见，`Aris-guanpao-z` 缩为 0。游戏画面可见浅色投射物。 | 基岩版通过 |
| 爱丽丝斜向投墙 | `229` | `-1030792151031` → `projectile/0003`，第 18303 刻选 `air`，第 18310 刻转 `ground`，绑定并绘制 98 个骨骼的模型（含两根朝向载体）。这次第一条客户端实体记录在离手后第 5 刻。Java 对照为第 1 刻。 | 可复现的离手显示延迟 |

| 爱丽丝忠诚 III | `243` | `-1030792151034` → `projectile/0003`，同一实体从墙边向玩家移动，返回后实体消失，原手持槽复原。 | 返回和手持恢复通过 |
| 战术酒狐斜向投墙 | `257` | `-1030792151032` → `projectile/0001`，绘制 1 个作者骨骼及 2 个朝向载体。双端可见戟尖朝飞行方向、入墙后戟杆留在墙外。基岩版墙面命中后亮度较低。 | 静态外观和朝向通过 |

Java 的同刻换手组中，`242`、`244` 在飞行和入地阶段都读成 `minecraft:stick`，所以作者按弓、弩区分的分支都不会打开。延迟切手组 `262`、`264` 分别读取 `minecraft:bow`、`minecraft:crossbow`。Java 实测记录了 YSM 实体查询的返回值和游戏画面。骨骼的逐项缩放来自基岩版绘制诊断。[Java 的发射物品读取](https://github.com/YesSteveModel/YesSteveModel/blob/15c2c25f5b50f54ee099bc474483dc4b588d956d/src/main/java/com/elfmcys/ysm/mixin/AbstractArrowEntityMixin.java)

0.29.0 中，三叉戟 `-1026497183740` 的功能开关、归属、匹配都通过，替换渲染器创建了，随后停在 `animation / no_frame_for_replacement`。第一处故障是三叉戟的原生绘制入口，旧特征串在客户端中命中四处。0.29.1 让数据驱动实体、船和投出三叉戟各自定位并注册绘制入口，三叉戟进入共用动画和绘制流程。

0.29.1 剩余差异中，爱丽丝出手延迟最早落在客户端实体出现阶段。其命中特效已经过归属、匹配、`ground` 选择及网格绘制，颜色差异仍需在实际绘制与命中姿态上核对。两份原包均已取得，故障可以用真实原包复现。

0.29.5 继续沿真实碰撞点复测爱丽丝和战术狐。基岩新增了碰撞时刻、客户端插值、动作选择和绘制的同 ID 记录及放手对齐视频。最新原包实投已恢复爱丽丝命中时的黑芯和蓝边，个别帧仍有蓝片遮挡；战术酒狐斜插墙后亮度仍有差异。[三叉戟最新实测](0.29.5-跨端功能验收.md#三叉戟的实际命中时刻)

录像依次展示战术酒狐投墙、爱丽丝投墙、命中劫掠兽和忠诚返回。游戏输入使用测试世界内的真实蓄力和释放，镜头为固定侧视，播放为半速。
